# SECURITY.md — Bao Message

Threat model: a hobby app for a few friends. We want (a) outsiders can't get in, (b) users can't read each other's private chats, (c) if the database is dumped or Supabase is breached, message contents are unreadable. We are NOT defending against a compromised device or a malicious owner who ships evil client code.

## Phase 1 baseline (mandatory before anyone uses it)
1. **HTTPS everywhere** — Vercel + Supabase do this by default. Never call Supabase over http.
2. **Auth**: Supabase magic-link email OTP. No passwords stored anywhere. Set OTP expiry to 10 min in Supabase Auth settings. Enable "Confirm email".
3. **Allowlist enforced server-side**: a `before insert` trigger on `auth.users` rejects signups whose email isn't in `public.allowlist` (see SCHEMA.sql). Client-side checks are cosmetic only.
4. **Row Level Security ON for every table**, policies in SCHEMA.sql. Rule of thumb: a row is visible only if `auth.uid()` is a member of the row's conversation.
5. **Keys**: only the anon key ships to the browser. Service-role key lives only in Vercel env vars for server routes (and in Phase 1 you likely need none).
6. **Rate limiting**: Supabase Auth has built-in email rate limits; leave defaults. Add a simple check constraint `length(body) <= 4000`.
7. **Encryption at rest**: Supabase encrypts disks at rest (AES-256). This protects against stolen hardware, not against a DB dump — hence Phase 2.
8. **Don't log message bodies** anywhere (no `console.log(message)` left in prod, no analytics).

## Phase 2 — End-to-end encryption (server never sees plaintext)

Library: `tweetnacl` + `tweetnacl-util`. All crypto in the browser.

### Keys
- **Identity keypair** per user-device: `nacl.box.keyPair()` (X25519). Generated on first login on a device.
  - Private key stored in **IndexedDB** (not localStorage) as raw bytes; never sent to the server.
  - Public key uploaded to `profiles.public_key` (base64). If a user already has a public key from another device, see "Multi-device" below.
- **Conversation key** per conversation: 32 random bytes (`nacl.randomBytes(32)`), generated by whoever creates the conversation.
  - For each member, wrap it: `nacl.box(convKey, nonce, member.publicKey, mySecretKey)` → store in `conversation_keys (conversation_id, user_id, wrapped_key, nonce, wrapped_by)`.
  - When a member is added later, any existing member's client wraps the key for them.
  - Removing a member = rotate: generate a new conv key, re-wrap for remaining members, bump `key_version`. Old messages stay readable with the old key version (keep old wrapped keys).

### Messages
- Encrypt: `nonce = nacl.randomBytes(24)`; `ciphertext = nacl.secretbox(utf8(body), nonce, convKey)`.
- Store: `messages (ciphertext bytea/base64, nonce, key_version, sender_id, conversation_id, created_at)`. **No `body` column in Phase 2** — drop it after migrating (or leave null).
- Decrypt on read; cache plaintext in memory only (React state), never persist decrypted text.
- Last-message previews in the chat list: decrypt client-side too. Do not store previews server-side.

### Multi-device / key backup (so a new phone can read history)
Simplest sane option: **passphrase-encrypted key backup**.
- User sets a backup passphrase in Profile. Derive a key with `nacl.hash`-based PBKDF is weak — use WebCrypto `PBKDF2` (SHA-256, ≥ 600k iterations, random 16-byte salt) → 32-byte key.
- Encrypt the identity private key with `nacl.secretbox` under that key; store `{salt, nonce, ciphertext}` in `key_backups`.
- New device: enter passphrase → decrypt → restore identity key → all wrapped conversation keys become readable.
- Also offer a QR export of the raw private key for same-room device transfer (optional).
- Be honest in the UI: "If you lose your phone and forget your backup passphrase, your old messages are gone."

### What E2EE does NOT hide
Metadata: who talks to whom, when, message sizes, display names. Acceptable for this project — say so in the README.

## Checklist to verify before calling Phase 2 done
- [ ] `select body from messages` in the SQL editor shows nothing readable.
- [ ] A member removed from a group cannot decrypt messages sent after removal.
- [ ] Restoring on a second device with the passphrase shows full history.
- [ ] No plaintext in localStorage, IndexedDB, or network payloads (check DevTools).
- [ ] Private key never appears in any Supabase table or log.
